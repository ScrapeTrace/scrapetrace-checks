How this check works

Each feature has separate results for API exposure, availability and execution. A functional check passes when a session is created and its operation returns a non-empty response of the expected shape. Small session checks also record invalid-receiver rejection, cancellation and behavior after destruction. Expand a feature to see the input, output and errors.

The samples use English text, with English-to-French translation. Availability applies to these options and this page. A download may be needed to initialise an API for this origin even when related model files already exist. This page cannot inspect Chrome’s model folders.

At most two sessions run together, each with a 20-second deadline and a 65-second overall budget. A click can retry a ready API if user activation or another restriction prevents automatic creation. Sessions are destroyed after use. Readings and JSON exports stay in the tab. A successful call records functionality, not the identity of the implementation.

Automation: wait for #probe-complete[data-status="complete"] or window.__PROBE_RESULT__?.complete. Results are retained in the visible page and the JSON below. Navigation load alone is insufficient.
